## Concepts

### A — Field Guide

A temporary left-side sheet opened with **F1** (proposed). It dims the world,
does not pause it, and lists the complete control set. Point-and-click enabled
leads with a **CLICK ACTIONS** block; the always-available keys follow below.

- Best for new players and for checking a forgotten binding.
- Covers the Automatica panel while open, which is acceptable for a temporary
  reference.
- State is obvious from both the badge colour and the copy.

### B — Quick Bar

A compact always-on strip across the top-left. It shows only the essentials.
With point-and-click enabled it grows one short third line describing the
ground / object / enemy click behavior; `LMB` is highlighted amber. F1 still
opens Concept A for the full reference.

- Best for players who want a persistent cheat sheet without dimming the world.
- Intentionally smaller than the mission tracker and star summary; the mockups
  keep a gap to the pause cluster at 1920×1080.
- Below 1280 px wide it should collapse to two rows (recommendation, not shown).

### C — Split Wings

The controls are stacked vertically into two narrow edge panels: a **left
wing** for movement/world action and a **right wing** for systems/interface.
The middle third of the screen stays unobstructed.

- PnC OFF: left = move/act (WASD, Shift, LMB, mouse aim, Shift+LMB); right =
  build/items/navigation (Ctrl, E, hotbar, map, Esc, dialogue).
- PnC ON: left = click actions + move/aim; right = always-available world and
  interface keys.
- Both wings are vertically centred and edge-anchored. F1 hides them together.
- The left wing carries the state colour; the right wing stays neutral blue so
  it reads as the stable half.
- This is the best fit for the “two sides of the screen” request. The shipped
  version is the compact always-on variant: small top-left and bottom-right
  cards with no scrim, and F1 hides them together.

### D — Bottom Clusters (shipped)

Minimal floating keycaps anchored to the bottom edge, directly over the world:

- **Bottom-left:** W/A/S/D in a T, with a wide Shift key and a tiny SPRINT label.
  When point-and-click is on, WASD is hidden and only the Shift sprint key remains.
- **Bottom-right:** one merged LMB chip plus a Ctrl build chip. The LMB label
  follows the hovered target (USE / MINE / ATTACK / CHOP in manual mode;
  MOVE / INTERACT / CHASE in point-and-click mode). Shift attaches to that same
  LMB chip for the contextual DESTROY action.
- No panel, no scrim, no backgrounds behind the clusters; only the keycaps have
  a translucent fill and a soft shadow.
- Hovering a chip or holding a key lights the relevant keycap; releasing clears
  it. Window focus loss clears all highlights.
- The bottom-centre hotbar, health/stamina bars, minimap, missions and
  Automatica status are untouched.

## Copy

### Point-and-click OFF

| Key | Action |
| --- | --- |
| WASD / Arrows | Move |
| Shift | Sprint (hold) |
| LMB | Use / mine / attack |
| Mouse | Aim swings |
| Shift + LMB | Destroy placed object |
| Ctrl | Build mode |
| E | Inventory |
| 1–9 / Wheel | Hotbar |
| M | Map |
| Esc | Pause / close |
| Enter / Space | Dialogue |

### Point-and-click ON

Click actions:

| Key | Action |
| --- | --- |
| LMB | Ground: walk there |
| LMB | Object: walk + interact |
| LMB | Enemy: chase + attack |
| WASD | Cancel order + move |
| Esc | Cancel move order |

Always available: Shift sprint, Shift + LMB destroy, Ctrl build, E inventory,
1–9 / wheel hotbar, M map, Esc pause/close, mouse aim, Enter / Space dialogue.

Note in the sheet: **RMB / build mode / open panels are never intercepted.**

### Split Wings C copy

Left wing, PnC OFF: Move / Sprint; Use / mine / attack · hold; Aim swings;
Destroy placed object.

Right wing, PnC OFF: Build mode; Inventory; Hotbar; Map; Pause / close;
Dialogue.

Left wing, PnC ON: Ground walk; Object walk + interact; Enemy chase + attack;
Cancel order + move; Sprint; Aim swings.

Right wing, PnC ON: Destroy placed object; Build mode; Inventory; Hotbar; Map;
Pause / close; Dialogue. A note reads `RMB / build / UI never intercepted`.

## Decisions still open

1. **Concept:** A = temporary full sheet, B = one-line quick bar, C = left/right
   vertical wings. C matches the latest “two sides of the screen” request.
2. **Toggle key:** F1 is proposed. It is not bound today. Alternatives: `?`,
   `H`, or a pause-menu button only.
3. **Default visibility:** the shipped bottom clusters are on by default; F1
   hides them. Concepts A/B/C remain design history.
4. **Auto-sprint:** when the point-and-click auto-sprint setting is on, the
   sheet shows `AUTO-SPRINT: SETTINGS`. A live `AUTO-SPRINT ON` badge may be
   clearer.
5. **Rebinding:** the game supports rebinding movement, inventory and all nine
   hotbar slots. The overlay must read the live bindings, not hardcode the
   defaults shown in these drafts.
6. **Mobile:** these drafts are PC-only. Android keeps the existing touch HUD.

## Implementation notes (for a later task)

- Put the overlay above the gameplay HUD but below modals; never intercept
  world clicks while it is visible.
- Do not pause the tree or dim the world for the compact guide.
- Hide the guide while pause/inventory/crafting panels are open.
- Respect `Global.ui_safe_insets` and `Global.ui_scale`.
- The compact cards reserve the top-left and bottom-right corners so they do
  not collide with the mission tracker, Automatica panel, minimap or hotbar.
- Use the existing panel palette and the theme font.
